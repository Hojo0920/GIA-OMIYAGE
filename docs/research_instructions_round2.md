# 第2ラウンドの追加ルール（INSTRUCTIONS.md に上書きで効く）

前回は検索の上限（1ターン200回・全担当で共有）を使い切り、多くの店が未調査で終わった。今回は上限が回復している。次を守ること。

1. **検索の予算（最重要）**: プロンプトに書かれた「あなたの上限N回」を超えて WebSearch を呼ばない。呼び出し1回を1回と数え、自分で回数を数えておく。
   上限は全担当で共有されており、超えると他の担当の分を奪う。残りが2回になったら調査をやめ、出力を仕上げて報告する。
2. **こまめに保存**: 1店の調査が終わるたびに、出力のJSONを（上書きで）保存する。途中で打ち切られても結果が残るようにするため。最後にもう一度、全店分を保存し直す。
3. **mode は "extended" を基本にする**: 1回の呼び出しで商品ラインの入数別価格がまとめて返る。クエリには「商品名・入数・価格・税込・賞味期限・原材料・個包装」を入れる。
   店の公式・通販ドメインは、同じフォルダの known_Gn.md に分かっている範囲が書いてある。未特定の店は、店名だけの検索（allowed_domains なし）で1〜2回で特定する。
4. **既知データ**: 同じフォルダの known_Gn.md（Gn はあなたのグループ名）に、店ごとの「いま分かっていること」と「まだ分からないこと」がある。確認レベルAの項目は再確認しない。
   「未確認」の項目（原材料表示・個包装の有無・日持ち・他の入数・他の商品）を優先して埋める。既知の商品も、新しく分かったことがあれば出力に含める（こちらで統合する）。
5. **優先する商品**: 常温で日持ちし、箱入りまたは個包装で、税込2,300円以下の入数があるもの。金沢らしさのある菓子（上長は「センスのいいもの」を求めている）。
   生菓子・要冷蔵・日持ち7日未満・チョコがけ（溶ける）・酒類は skipped に1行で残すだけでよい。
6. **メモは利用者向けの日本語で書く**: notes・scope_note・unresolved に、内部のデータ項目名（ingredient_flags、null、confidence、price_tax_incl、JSON など）や、検索の回数・上限の話を書かない。
   値の食い違いは「【食い違い】A円とB円が出た」の形で、事実だけを書く。
7. **税別表示しか見つからない場合**: price_tax_incl は null にし、options の evidence に「810円+税」「1,100円（税別）」のように原文の価格表記を必ず残す（こちらで8%換算する）。
8. 出力形式は INSTRUCTIONS.md と同じ。JSON の "group" には指定された名前（G8 など）を入れる。担当外の店は調べない。
